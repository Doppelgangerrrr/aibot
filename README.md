# SupportAI: ИИ-консультант для Telegram с базой знаний

Telegram-бот, который отвечает клиентам на вопросы по базе знаний компании (цены, сроки, гарантия, адрес) на основе Claude. Когда ответа в базе нет, клиент просит человека или ситуация требует решения сотрудника, бот сам передаёт диалог живому оператору. Оператор отвечает клиенту прямо из Telegram.

Демо настроено под мастерскую по ремонту техники. Под другой бизнес бот перенастраивается заменой файлов в папке `knowledge/`, код трогать не нужно.

## Возможности

**Для клиента**
- отвечает на естественном языке и помнит контекст диалога (история хранится в SQLite и переживает перезапуск бота);
- не выдумывает: если факта нет в базе знаний, говорит об этом и зовёт оператора;
- кнопки «Позвать оператора» и «Новый диалог»;
- пока модель думает, в чате показывается индикатор «печатает…».

**Для оператора и администратора**
- карточка «🆘 Нужен оператор»: кто клиент, причина, суть вопроса и последние сообщения диалога;
- ответ клиенту — обычный reply на карточку, бот доставит его от имени оператора. ИИ видит ответы оператора и учитывает их дальше;
- `/stats`: пользователи, вопросы всего и за сегодня, сколько раз передавали оператору;
- `/kb` и `/reload`: посмотреть базу знаний и перечитать её с диска без перезапуска.

**Под капотом**
- Claude API (`claude-opus-5-5`, effort `low` для быстрых и недорогих ответов в чате);
- передача оператору — через tool use (`escalate_to_operator`, строгая схема `strict: true`): модель сама решает, когда нужен человек;
- prompt caching: база знаний кэшируется, повторные запросы оплачиваются по цене чтения из кэша (~10% от обычной стоимости входа). Попадания в кэш видны в логах (`cache_read=...`);
- server-side fallback: если модель отказывается отвечать, запрос автоматически переигрывается на запасной модели;
- rate limit на пользователя (защита бюджета API), очередь сообщений на пользователя, обработка ошибок API без падения бота.

## Стек

Python 3.11+, aiogram 3, Anthropic Python SDK, SQLite (`aiosqlite`).

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env          # Linux/macOS: cp .env.example .env
```

Заполните `.env`: `BOT_TOKEN` (от [@BotFather](https://t.me/BotFather)), `ANTHROPIC_API_KEY` ([platform.claude.com](https://platform.claude.com/settings/keys)), `ADMIN_IDS` (ваш id, узнать у [@userinfobot](https://t.me/userinfobot)). Для общего чата операторов добавьте бота в группу и укажите её id в `OPERATOR_CHAT_ID`.

```bash
python -m bot
```

## Как адаптировать под клиента

1. Замените файлы в `knowledge/` на информацию о бизнесе клиента: любые `.md` или `.txt`, можно с таблицами.
2. Поправьте приветствие в `bot/handlers/user.py` и, при необходимости, тон ответов в `INSTRUCTIONS` в `bot/llm.py`.
3. Отправьте боту `/reload`.

База знаний целиком передаётся модели и кэшируется. У API есть минимальный размер кэшируемого префикса (порядка тысячи токенов и выше, зависит от модели), поэтому крошечная демо-база может не кэшироваться (`cache_read=0` в логах); на реальной базе клиента кэш срабатывает. Это лучший по качеству вариант для баз до нескольких сотен страниц; для очень больших баз нужен поиск по фрагментам (RAG).

## Структура

```
bot/
├── __main__.py      # точка входа
├── config.py        # настройки из .env
├── llm.py           # Claude: системный промпт, кэш, tool use, обработка ошибок
├── knowledge.py     # загрузка базы знаний из папки
├── handoff.py       # передача диалога оператору
├── db.py            # SQLite: пользователи, история, передачи оператору, статистика
└── handlers/
    ├── user.py      # чат клиента с ИИ, rate limit
    └── admin.py     # ответы оператора, /stats, /kb, /reload
knowledge/           # база знаний демо-мастерской
```
